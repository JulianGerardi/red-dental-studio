# Confidentally design system

Este design system **no es una copia** de la app: lee el mismo código. Si cambiás un color o un componente en la app, cambia acá.

## Ir a…

Todas las páginas del design system. Buscá por nombre o hacé clic para abrirla.

<Mapa />

## Cómo está ordenado

| Sección | Qué hay | Para qué |
|---|---|---|
| **Foundations** | Colores, tipografía, radios y sombras. | Los valores base, leídos de `src/index.css`. |
| **Elements** | Page header, Buttons, Fields, Tabs, Pills, Cards, Tables, Navigation y Patient menu. | Las piezas estándar para armar pantallas. Cada una tiene un **Playground** para personalizarla y probarla, sus estados, sus medidas y sus colores. |
| **Components** | Las piezas de cada módulo (Dashboard, Patients, Scheduling, Clinical…). | Ver y probar cada componente de la app por separado. |
| **Pages** | Las 30 pantallas de la app. | Ver cada pantalla completa, con sus rutas reales. |
| **Audit** | Colores sin token, estados, duplicados, cobertura y lo que el código hace hoy. | Para quien migra código: qué se aparta del estándar. |

## Qué tiene cada página de componente

Es la biblia del UX de Confidentally: cada componente de la app, documentado y funcionando.

1. **Qué es y cuándo usarlo**, arriba de todo.
2. **Playground**: el componente con controles para cambiarlo y probarlo (panel *Controls*).
3. **Estados**: vacío, cargando, error, deshabilitado, seleccionado… los que tenga.
4. **On each device**: cómo se ve en celular (390px), tablet (768px) y escritorio (1280px), usable adentro.
5. **Where it is used**: qué pantallas de la app lo usan, leído del código.
6. **Design decisions**: por qué es como es, leído de los comentarios de su código, cada decisión con su línea.
7. **Source**: el código del componente y de sus historias.

Lo que falta para completarla se ve en *Audit / Documentation coverage* → *UX bible*.

## Cómo probar un elemento

1. Abrí un elemento en **Elements**, por ejemplo *Buttons*.
2. Entrá a **Playground**.
3. En el panel **Controls** (abajo o a la derecha) cambiá variante, tamaño, texto, estado… El elemento cambia en vivo.
4. **Show code** muestra el código de lo que armaste, listo para copiar.

## Qué se actualiza solo y qué no

| Si vos… | El design system… |
|---|---|
| Cambiás un token en `src/index.css` | Se actualiza solo. |
| Cambiás un componente existente | Se actualiza solo. |
| Cambiás un color escrito a mano (`text-[#09090b]`) | Cambia solo ese lugar. Por eso conviene pasarlos a tokens: ver *Audit / Colors in code*. |
| Agregás un componente nuevo | Hay que crear su `.stories.tsx`. `npm run ds:coverage` lista los que faltan. |

## Comandos

```bash
npm run storybook        # abre el design system en localhost:6006
npm run ds:coverage      # lo que todavía no tiene story
npm run build-storybook  # versión estática
```
