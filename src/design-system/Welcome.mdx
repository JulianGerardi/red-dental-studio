# Red Dental Studio design system

Este design system **no es una copia** de la app: lee el mismo código.

- **Los tokens** (colores, radios, sombras, tipografía) salen de `src/index.css`. Si cambiás un valor ahí, cambia la app y cambia esta documentación.
- **Los componentes** de cada story se importan de `src/components`. Si cambiás un botón, cambia acá.
- **Las auditorías** (colores escritos a mano, tamaños de texto, radios) se calculan leyendo el código fuente en cada build.

## Qué se actualiza solo y qué no

| Si vos… | El design system… |
|---|---|
| Cambiás un token en `src/index.css` | Se actualiza solo. |
| Cambiás un componente existente | Se actualiza solo. |
| Cambiás un color escrito a mano (`text-[#09090b]`) | Cambia solo ese lugar. Por eso conviene pasarlos a tokens: ver *Foundations / Color audit*. |
| Agregás un componente nuevo | Hay que crear su `.stories.tsx`. `npm run ds:coverage` lista los que faltan. |

## Cómo se usa

```bash
npm run storybook        # abre el design system en localhost:6006
npm run ds:coverage      # componentes de la app que todavía no tienen story
npm run build-storybook  # versión estática
```
